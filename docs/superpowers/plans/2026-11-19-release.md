# Tawsela Release Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Repair the booking product and publish a free-tier cash-only web release.
**Architecture:** Existing Flutter BLoC layers with Firestore transactions and default-deny Security Rules. Approved drivers use the same app. Vercel hosts web assets and a geocoding proxy.
**Tech Stack:** Flutter 3.50, Dart, Firebase Auth/Firestore, Node.js tests, Vercel.
**Spec:** docs/superpowers/specs/2026-11-19-release-design.md

## Global Constraints
- Cash only; no simulated success or invented user data.
- All persisted user data scoped by authenticated UID.
- Only approved drivers accept and advance rides.
- No paid service provisioning.

## Review Focus
- Rapid double taps and cancellation while a network operation is pending.
- Switching accounts and signing out during async work.
- Failed/offline writes must remain retryable without duplicate trips.
- Invalid coordinates, unresolvable text, and denied location permission.
- Ownership, driver availability and immutable financial/trip fields.
